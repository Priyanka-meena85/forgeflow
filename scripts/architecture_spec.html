01 Executive Architectural Overview & Core Tenets

ForgeFlow is an enterprise SaaS platform engineered specifically for heavy industrial equipment manufacturers. In heavy B2B sectors (commercial HVAC rooftop units, sanitary lobe pumps, high-tonnage servo presses, polymer extrusion skids, proportional hydraulics), marketing content directly touches mission-critical operating parameters where hallucinations in tolerances cause equipment failure and contractual liability.

1. Zero-Hallucination Determinism

AI prompt chaining is mathematically and logically bounded by certified engineering standards (ASHRAE 90.1, ASME Section VIII, 3-A Sanitary, IATF 16949) and customer-ingested OEM manuals. Speculative parameter generation is strictly prohibited by AST validators.

2. Human Engineer-in-the-Loop (HITL)

No technical article or operating envelope table can be published or exported without verifiable sign-off from a credentialed applications engineer. Reviewer credentials (PE, ASHRAE Fellow) are injected into Schema.org reviewedBy metadata.

3. Multi-Tenant Strict Isolation

Logical tenant segregation enforced across database queries, object storage, RAG vector namespaces, CMS API credentials, and per-tenant sliding window rate limiters.

4. Dual-Mode Resilient Database Engine

High-availability PostgreSQL cluster coupled with continuous non-blocking socket health probing (<20ms) and an instant in-memory transactional fallback store ensuring 100% zero-downtime execution.

04 Deterministic RAG & Generation Pipeline

Industrial content cannot rely on unconstrained LLM completion. The generation engine enforces an 8-stage bounded pipeline with deterministic constraints:

Stage 1
Taxonomy Seed Ingestion

User selects heavy vertical (e.g. Commercial RTU HVAC), equipment asset, failure mode (Compressor Flooded Starts), and governing standard (ASHRAE Standard 90.1).

Stage 2
OEM Manual Vector RAG Retrieval

Ingested manufacturer PDF manuals and service SOPs are queried for exact model numbers, suction superheat bounds (4°F threshold), and oil viscosity minimums (32 cSt).

Stage 3
Deterministic Prompt Chaining

System prompt mandates exact numeric limits and restricts output to diagnostic checklists, failure root causes, and corrective SOPs. Generic marketing language is banned.

Stage 4
AST Anti-Fluff & Regulatory Allowlist Gate

Post-generation Abstract Syntax Tree (AST) parser strips non-falsifiable superlatives (e.g., "cutting-edge", "game-changing") and validates external links against official registries.

Stage 5
Direct Answer Capsule & Multi-Entity Schema Generation

Generates a 45-word direct answer capsule optimized for AI extraction and validates multi-entity JSON-LD graphs (TechArticle, HowTo, and FAQPage schemas).

Stage 6
Human Applications Engineer Sign-Off

Draft enters IN_REVIEW state. Licensed Professional Engineer (PE) audits operating envelopes and signs off via GUI or team Slack/Teams bot.

Stage 7
Attribution Metadata Injection & Audit Logging

Engine binds reviewer credential badge to schema and writes immutable entry to AuditLog with cryptographic timestamp and IP signature.

Stage 8
Multi-Head Direct CMS Syndication

1-Click publication dispatches structured payloads to WordPress, Webflow, HubSpot, or signed enterprise outbound webhooks.

Dual-Mode Resilient Database Engine Implementation

In high-reliability enterprise environments, database timeouts must never freeze client UI sessions. ForgeFlow implements a continuous socket-probing proxy in lib/db.ts:

Health Probe
Non-Blocking Socket Probe (<20ms)

A native Node.js socket tests PostgreSQL connectivity on port 5432 with an 80ms timeout. State is cached on globalThis.__forgeflow_pg_available__ across Next.js Turbopack chunks.

Fallback
Instant Zero-Latency Fallback

If PostgreSQL is unreachable, requests route instantaneously to an in-memory transactional store with zero connection hangs (<50ms response vs 4,200ms TCP timeout).

Production
Strict Production Enforcement

When NODE_ENV=production and ENFORCE_MANAGED_DATABASE=true, silent fallback is disabled, throwing explicit infrastructure errors to trigger on-call alerts.
